The implemented policy makes ordinary browser navigation open Anacan, then fall
back to the appropriate store. It is live on Google/API and prepared for the
Lovable app host. The installed application uses its bundled WebView entry and
remains exempt from the browser launcher.

Verified administrators can open `/?web=admin`. The query alone grants no access:
the existing backend-scoped session, live `auth.getUser()` identity and server
`has_role(..., 'admin')` must all pass. Non-administrator login is rejected and
locally signed out. Logout, focus/visibility and a 30-second role check revoke
preview access. Moderator entry retains its own server-verified role gate.

The public marketing website `anacan.az`/`www.anacan.az` keeps its independent
Google SSR runtime, 21 languages, translated permalinks and legacy301 contract.
See [the website deployment](WEBSITE_GOOGLE_20261006.md).

## Navigation contract

- iOS: registered `anacan://` scheme, App Store
  `https://apps.apple.com/app/id6758301924`.
- Android: package-scoped `intent://` with the Google Play fallback
  `https://play.google.com/store/apps/details?id=com.atlasoon.anacan`.
- Store fallback runs after 2200ms and is cancelled by `pagehide` or a hidden
  document when the application opens. Desktop Mac uses App Store; other desktops
  use Google Play. iPad desktop-mode browsers are identified separately.
- Article slug, supported language and six module IDs are retained. Arbitrary
  queries, credentials and external destinations are excluded from app links.
- `sleep`, `feeding`, `diaper` return to their home modules; `hospitalBag` maps to
  `/tool/hospital`, `babyGrowth` to `/tool/baby-growth`, and `calendar` to `/calendar`.
- Legal documents, localized terms/privacy, recovery/provider/payment paths,
  brand portal and required API/media/assets/control paths keep their handlers.
- Recovery/payment router navigation leaving its exception reloads through the
  entry decision. Missing-resource SPA fallback cannot initialize consumer Auth.
- Google/API slash-normalization redirects are relative and preserve HTTPS.

`src/web-entry/early.js` and `scripts/app-entry/plugin.mjs` produce a small,
SDK-free hashed IIFE/CSS before the consumer bundle. The root and all399 blog
HTML pages reference it. Blog content, canonical/hreflang, metadata, FAQ/schema,
images and sitemaps remain in the HTML. Browser rendering follows the requested
mobile-entry policy; verified admin preview retains web blog navigation.

Public legal reads use anonymous REST without consumer-session initialization.
The API web build retains its existing direct Azure origin/auth-storage realm;
Source-first bootstrap is a separate native admission protocol. Brand portal
sessions remain independent and membership remains server-enforced.
