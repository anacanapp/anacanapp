## Premium funnel with Epoint (2026-11-06)

`anacan.az/website/premium/` sells web Premium in AZN through Epoint. The user approved the prices on 2026-11-06:

| Plan | Price | Term |
| --- | --- | --- |
| Monthly | 3.99 ₼ | 1 month |
| Yearly | 26.99 ₼ | 12 months |

Both are fixed-term passes. They do not renew automatically.

**Prices and switch.** Prices live server-side in `app_settings.web_premium_epoint`, set to `{enabled, prices}`.

**Checkout**
1. `web-shop` GET returns `premium: {ready, currency, prices}`.
2. POST `{kind:'premium', plan, email, language}` creates a `web_premium_orders` row. The limit is 10 orders per hour per e-mail.
3. The response returns the Epoint checkout URL, `https://ecomm.pashabank.az:443/...`. The client accepts only `https://*.az` URLs, with an optional `:443` port.

**Payment result**
- The shared Result URL `epoint-payment?action=callback` sends funnel orders to `_shared/web-premium-result.ts`.
- That handler confirms the payment with `get-status` and checks that the amount matches the order.
- It then calls `web_premium_epoint_grant_v1`, which is idempotent and checks the amount. The grant writes `web_subscriptions` with provider `epoint`, `cancel_at_period_end = true`, and a period of 1 or 12 months.
- If another Epoint pass for the same e-mail is still running, the new period starts when that one ends.

**Linking to an account**
- `web_subscription_link_email_v1` links the subscription to an account whose e-mail is verified. Then `syncEntitlementForUser` runs.
- Otherwise the subscription is linked when the account signs in.

**Migration.** `20261106120000_web_premium_epoint.sql` is applied. Its `.cdc.json` enrolls `web_premium_orders` and guards it.

**Gateway.** The current gateway is `22755738…`. To roll back, use `/home/anacan-runner/rollback-funnel-epoint2-web-plan.json`.

**Copy.** For Epoint, the funnel shows only the first part of the `secure` line. The "cancel anytime" part is hidden because the passes do not renew.
